## 1) الرؤية والنطاق
**الجملة الحاكمة:** المنتج يدخل المخزن، يُفحص، يدخل الروتين، تُسجَّل نتائجه، وتُقارن — وكل قرار (استمر/أوقف/تجنّب) مبني على سجل وليس على الذاكرة.

**داخل النطاق:** مفكرة البشرة، المنتجات، المكونات والحساسية، الروتين والإنجاز، التجارب (اختبار منتج)، المقارنة والتقارير، الاكتشاف (كتالوج خاص بالمستخدم + بحث).
**خارج النطاق (v1):** قاعدة بيانات منتجات عالمية (تحتاج مزوّد بيانات — فجوة F-01)، منتدى عام (نستخدم Knowledge/مشاركة داخل الـ workspace)، تشخيص طبي.
**تنبيه صحي ملزم:** النظام أداة تنظيم وتوثيق؛ لا يشخّص ولا يصف علاجًا. تظهر عبارة إرشادية في المحلل والتقارير.

## 3) المبادئ والحدود بين الأقسام
### 3.1 الاستقلال
Skincare OS يعمل وحده. غياب أي قسم آخر يُخفي الميزة المرتبطة فقط (مصفوفة 3.3).

### 3.2 من يملك ماذا
| البيانات | المالك | غير المالك |
|---|---|---|
| المنتجات، المكونات، الروتين، المفكرة، التجارب | Skincare | غيره يقرأ عبر الأحداث فقط |
| النوم والمزاج | Skincare يسجّل نسخة خاصة به؛ إن وُجد Habit يُستورَد منه كقراءة | لا نكتب في Habit |
| سعر الشراء | يُسجَّل هنا كمعلومة؛ **لا** يُنشئ حركة مالية. حركة Finance تُنشأ بحدث اختياري | لا نعدّل Finance |
| قائمة الأمنيات | Skincare (نطاق البشرة) | Shopping Wishlist يستقبل نسخة بحدث |
| الصور | Skincare (تخزين خاص) | لا مشاركة افتراضيًا |

### 3.3 مصفوفة التدهور
| غياب | السلوك |
|---|---|
| Habit | حقول النوم/المزاج تُدخل يدويًا |
| Sports | الرياضة تُدخل يدويًا |
| Shopping Wishlist | الأمنيات تبقى داخلية |
| Finance | السعر معلومة فقط |
| Knowledge | لا روابط مقالات |
| تخزين الصور غير متاح | المفكرة تعمل بنص فقط، مع تنبيه واضح |

### 3.4 المبادئ الحاكمة (ملزمة)
1. **الصور حساسة افتراضيًا** (خاصة بصاحبها؛ لا ظهور في أي لوحة مشتركة).
2. **التفاعل السلبي سجل لا يُمحى بسهولة:** يُؤرشف ولا يُحذف إن كان مرتبطًا بمنتج.
3. **كل استنتاج يُعرض كمؤشر لا كحقيقة:** "ارتباط ملحوظ" وليس "سبب".
4. **لا أرقام مخترعة:** الحدود الافتراضية (مثل أيام الاختبار) قابلة للتعديل ومكتوبة في الإعدادات.
5. **المقاييس مشتقة:** لا نخزّن "عدد الأيام" أو "نسبة الالتزام".
6. **المكوّن المسبب للحساسية يحذّر ولا يمنع** (قرار المستخدم أخيرًا).
7. **الإدخال بدقائق قليلة:** تسجيل يوم كامل في المفكرة لا يزيد عن 5 حقول مطلوبة كحد أقصى.

### 3.5 الملكية والخصوصية
مستوى النظام شخصي (scope: personal). المشاركة الاختيارية للمفكرة بصيغة "للعرض فقط" مع شخص محدد (§13).

## 4) النموذج المفاهيمي
```
Product ──(عبوة)──► ProductUnit ──► RoutineStep ◄── Routine
   │                    │                 │
   ├── IngredientList ─► Ingredient       └─► RoutineLog (إنجاز يومي)
   │                    └─► Flag (مفضل/حساس/تجنّب)
   └── Reaction (تفاعل سلبي)          Trial (تجربة) ──► DiaryEntry ──► Photo
                                          └──────────────► Report (مقارنة)
```
- **Product** هو التعريف (الاسم، الماركة، الفئة، المكونات).
- **ProductUnit** هي العبوة الفعلية (سعر، فتح، انتهاء، استهلاك) — منتج واحد قد تكون له عدة عبوات عبر الزمن.
- **Trial** غلاف لتجربة منتج: بداية، نهاية، سؤال ("هل يخفف البثور؟").

## 6) محرك الحسابات والدوال
### 6.1 صلاحية العبوة
```
effective_expiry(unit) = min( unit.expiry_date , unit.opened_date + unit.pao_months )   // ما هو معرَّف منهما
days_left = effective_expiry − today
state = Finished    إن finished_date موجود
      = Expired     إن days_left < 0
      = ExpiringSoon إن days_left ≤ settings.expirySoonDays
      = Unopened    إن لا opened_date ولا started_use_date
      = Active      غير ذلك
```
- إن لم يُعرف أي تاريخ: `state = Active` و`days_left = null` ("غير معروف") — لا نخمّن.

### 6.2 الالتزام بالروتين
```
due(step, date)  = حسب frequency/days_of_week؛ TimesPerWeek لا تُلزم يومًا محددًا
adherence(date)  = done_steps(date) ÷ due_steps(date)      (null إن due = 0)
adherence_week   = Σ done ÷ Σ due   (مرجَّح بعدد الخطوات وليس متوسط نسب)
```
- الخطوة المتخطاة بسبب مسجَّل (`skipped_reason`) تبقى في المقام ما لم يكن السبب "يوم راحة".
- سلسلة الالتزام: أيام متتالية `adherence ≥ 0.8` (العتبة في الإعدادات `adherenceThreshold`)؛ اليوم الجاري المعلّق لا يكسر السلسلة.

### 6.3 الترتيب الذكي للخطوات (قاعدة ثابتة)
ترتيب افتراضي حسب الفئة: `Cleanser → Toner → Treatment/Exfoliant → Serum → Eye → Moisturizer → Sunscreen (AM فقط) → Oil/Balm`. يمكن للمستخدم تجاوزه يدويًا؛ التجاوز يُحترم ولا يُعاد ترتيبه تلقائيًا بعد ذلك. زر "رتّب" يعرض **معاينة** قبل التطبيق.
- **تحذيرات تعارض (مؤشرات لا منع):** مكونات مصنّفة Exfoliant مع Exfoliant آخر في نفس الروتين؛ Sunscreen في روتين PM؛ نفس المنتج مرتين في الروتين.
- لا يوجد جدول "تفاعلات دوائية" ولا ادعاء علمي؛ التحذيرات مبنية على وسوم الوظيفة فقط.

### 6.4 تحليل قائمة المكونات
```
parse(raw):  فصل بالفاصلة/السطر/النقطة العلوية → تطبيع (حروف صغيرة، حذف أقواس التركيز)
match:       تطابق تام مع inci_name أو aliases؛ غير المطابق يُنشأ كـ source=User, flag=None وبحالة "غير مصنّف"
order:       الترتيب في القائمة يُحفظ (الأعلى = الأكثر تركيزًا عادةً) ولا نحسب نسبًا مئوية
```
**مخرجات الفحص `scan(product, profile)`:**
- `avoid_hits` = مكونات flag=Avoid أو Sensitive → تحذير أحمر/برتقالي.
- `concern_notes` = لكل اهتمام في الملف: عدد المكونات `Helps` وعدد `Caution`.
- `favorites` = مكونات flag=Favorite الموجودة.
- `unclassified` = العدد غير المصنَّف.
- `verdict` ∈ {`Suitable`, `Review`, `Avoid`}:
  - `Avoid` إن وُجد مكوّن Avoid/Sensitive؛
  - `Review` إن وُجد Caution لاهتمام المستخدم أو unclassified > 30% (**حد افتراضي قابل للتعديل**)؛
  - `Suitable` غير ذلك.
- الفحص **إرشادي** ويُظهر دائمًا عدد المكونات غير المصنفة ("نتيجة جزئية").

### 6.5 البحث والفلاتر (على كتالوج المستخدم)
فلاتر: فئة، ماركة، حالة، سعر (من–إلى)، يحتوي/لا يحتوي مكوّنًا، verdict، قائمة. بحث نصي على الاسم/الماركة/المكونات. الترتيب: الصلة، الأحدث، السعر. المقارنة بين حتى 3 منتجات: جدول (المكونات المشتركة/المختلفة، السعر، verdict).

### 6.6 مقارنة التقدم (الفترة أ مقابل الفترة ب)
- الفترتان تُختاران بنافذة أيام (افتراضي `comparisonWindowDays`).
```
avg_skin(period) = متوسط skin_rating للأيام المسجلة فقط (null إن < 3 أيام مسجلة)
delta = avg_skin(B) − avg_skin(A)       // يُعرض مع عدد الأيام ("بناءً على n يوم")
```
- **الارتباط بنمط الحياة:** لكل متغير (نوم، مزاج، رياضة) نحسب متوسط skin_rating في الأيام "الأعلى" مقابل "الأدنى" من الوسيط خلال الفترة. تُعرض النتيجة فقط إذا كان عدد الأيام المسجلة ≥ 14 (حد قابل للتعديل)، وبعبارة "ارتباط ملحوظ في بياناتك" وليس سببًا.
- **التأخير:** خيار "قارن البشرة بنوم الليلة السابقة" (lag 1 day) لأن أثر النوم لا يظهر يومه (🛠️ قرار تصميم؛ يُعرض كخيار وليس كحقيقة).
- مقارنة الصور: نقطتان زمنيتان بنفس `angle/area`؛ إن اختلفت الزاوية يظهر تنبيه "غير قابلة للمقارنة بدقة".

### 6.7 نتيجة التجربة (Trial)
```
day_n = today − start_date + 1
adherence_trial = التزام الخطوات التي تحتوي المنتج خلال التجربة
baseline_avg = متوسط skin_rating لآخر 7 أيام مسجلة قبل البداية
trial_avg    = متوسط skin_rating خلال التجربة
reactions    = تفاعلات المنتج خلال التجربة
```
المخرجات: `delta = trial_avg − baseline_avg` مع عدد الأيام؛ إن `reactions` موجودة تظهر في الأعلى. **لا قرار تلقائي:** النظام يقترح فقط ("تفاعل Moderate+ — فكّر بالإيقاف")، والقرار `verdict` للمستخدم.
- تنبيه الثقة: إن كان أكثر من منتج جديد دخل الروتين في نفس الفترة تظهر عبارة "تجارب متزامنة — لا يمكن نسب التغيير لمنتج واحد".

### 6.8 تكلفة الاستخدام
```
cost_per_day(unit) = price ÷ (finished_date|today − started_use_date + 1)
```
تُعرض فقط عند توفر السعر وتاريخ البدء؛ العملات المختلفة لا تُجمع.

### 6.9 تقارير دورية
أسبوعي/شهري: التزام، متوسط البشرة، أيام بها تفاعلات، منتجات قاربت الانتهاء، تجارب جارية. كلها مشتقة وقت الطلب.

## 9) دورات الحياة وقواعد التكامل
### 9.1 دورة حياة المنتج
```
Wishlist → Owned → In Use → Finished
                    │   └→ Stopped (سبب مسجل)
                    └→ Avoid (من تفاعل أو قرار)
```
- `In Use` تلقائيًا عند أول سجل روتين منجَز (قابل للتراجع).
- `Finished` عند تعبئة `finished_date` للعبوة الوحيدة النشطة.
- `Avoid` يُقترح تلقائيًا عند تفاعل Moderate+ ويؤكده المستخدم.
- العودة من Avoid/Stopped تحتاج تأكيدًا.

### 9.2 قواعد التكامل (LV)
| # | القاعدة |
|---|---|
| V-01 | إدخال مفكرة بتاريخ مستقبلي مرفوض |
| V-02 | `opened_date ≥ purchase_date`، و`expiry_date` لا تسبق `purchase_date` |
| V-03 | `skin_rating`، `mood`، `sleep_quality` بين 1 و5؛ `sleep_hours` بين 0 و24 |
| V-04 | لا يضاف منتج `Avoid` للروتين دون تأكيد؛ ولا `Finished/Stopped` |
| V-05 | تفاعل `Severe` لا يُحذف |
| V-06 | حذف صورة يحذف الملف وصورته المصغرة معًا |
| V-07 | تجربة واحدة `Running` لكل منتج |
| V-08 | سجل الروتين idempotent عبر `client_generated_id` |
| V-09 | حذف منتج له عبوات/تفاعلات/تجارب ممنوع؛ أرشفة |
| V-10 | قيمة الخيار في الإعدادات تتحقق من الحدود (`trialDays` 7–90، `expirySoonDays` 1–180) |

### 9.3 العمليات المركّبة
- **ابدأ تجربة:** ينشئ Trial + يربط المنتج بالروتين (بمعاينة) + يحدد خط الأساس + ينشئ تذكير صورة "قبل".
- **أنهِ التجربة:** يحسب §6.7 ويطلب `verdict`، ويحدّث حالة المنتج بعد تأكيد.
- **سجّل تفاعلًا:** ينشئ Reaction + يقترح Avoid + يقترح مراجعة المكونات المشتبه بها + يعرض إيقاف المنتج من الروتين.
- **سجّل يومي سريع:** شاشة واحدة (التقييم + النوم + المزاج) ← حفظ؛ البقية اختيارية.
