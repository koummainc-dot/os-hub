- [ ] **G4 — صلاحيات وعزل:** اختبارات إيجابية وسلبية للمستخدم والعضو والمشاهد والمالك، بما في ذلك الخصوصية على الخادم/RLS.
- [ ] **G5 — البيانات القديمة:** مراجعة سجلات قائمة أو تصدير آمن للتحقق من الروابط اليتيمة/المتعارضة قبل أي migration أو إصلاح جماعي.
- [ ] **G6 — قاعدة البيانات:** مقارنة migrations المسجلة ومخطط Supabase الحالي ومخطط التطبيق؛ لا تطبق تغييرات إنتاجية قبل هذه المطابقة.
- [ ] **G7 — واجهة الاستخدام:** اختبار المسارات الحرجة بالعربية وRTL وحالات التحميل والخطأ والفراغ وتأكيدات الحذف.
- [ ] **G8 — النشر:** التحقق من نشر Preview/Production بنجاح بعد حل قيد Vercel، دون اعتبار نجاح build مرادفًا للنشر.
- [ ] **G9 — قرار النطاق:** اعتماد قائمة التأجيلات في القسم 3 أو إعادة فتحها كمتطلبات حالية.
- [ ] **G10 — الإغلاق:** تحديث هذا الملف بالأدلة والنتائج، ثم جعل PR جاهزًا للمراجعة؛ لا دمج قبل إغلاق البوابات المطلوبة.

### قاعدة تسجيل النتيجة لكل T

لكل بند من T-01 إلى T-85 يجب إضافة: **الحالة** (Pass / Fail / Not covered / Deferred)، و**اسم الاختبار ورقم assertion** أو خطوات القبول اليدوي، و**آخر commit تم التحقق عليه**. إذا لم يمكن ربط T بدليل مباشر، تسجّل `Not covered` ولا يُستنتج النجاح من مرور `npm test` وحده.
