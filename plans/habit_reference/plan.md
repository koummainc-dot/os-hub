# خطة تنفيذ: مواصفة Habit OS الموحّدة وواجهة عربية تفاعلية

## الهدف والملخص

تحويل الملفين الحاليين — مواصفة Habit OS الأصلية وملحق الجدولة ودورة حياة البيانات — إلى تصميم موحّد بلا تعارضات، ثم إنتاج:

1. **ملف مواصفة شامل بالعربية** يضم قرارات المنتج، مخطط الجداول والحقول والمفاتيح والقيود والفهارس والعلاقات وسياسات التغيير والحذف والحماية.
2. **ملف SQL قابل للمراجعة** يترجم التصميم العلائقي إلى مخطط قاعدة بيانات متناسق، ومناسب للتحويل إلى migrations عند تنفيذ backend لاحقًا.
3. **واجهة ويب عربية RTL تفاعلية** تشمل كل وحدات Habit OS وتسمح باستعراض وإنشاء وتعديل وأرشفة/حذف عناصرها في نموذج أولي.

المبدأ الحاكم: الاحتفاظ بتاريخ موثوق لكل شيء، مع إظهار 3–5 عادات تركيز يومية فقط؛ والعادات السيئة تقاس بالأيام النظيفة وسجلات الانتكاس، لا بسلاسل نجاح عادية.

## نطاق المنتج والأقسام

ستشمل المواصفة والواجهة:

- لوحة اليوم: ملخص التقدم، عادات التركيز، السلاسل، أيام النظافة، ولقطة الأسبوع.
- مكتبة العادات: الكل، النمو، الصيانة، التلقائية، المؤجلة، المؤرشفة، التفاصيل، الجدولة، الهدف، القياس، البداية والنهاية الاختيارية.
- السجل اليومي: تسجيل سريع، إدخال سابق، تعديل السجل وإلغاؤه، والكمية/الحالة/الملاحظة.
- سجل الانتكاسات للعادات السيئة وخطة التعافي وإعادة احتساب الأيام النظيفة.
- الجورنال: أكثر من تدوينة في اليوم، بحث حسب التاريخ/الوسم، حقول التأمل، المزاج والطاقة، وروابط متعددة للعادات.
- الكتب: المكتبة، الحالة، التقدم، جلسات قراءة متعددة، الصفحات/المدة، وملاحظات واقتباسات.
- التركيز الأسبوعي: مراجعة الأسبوع وربط عدة عادات دون تكرار سجلات العادات.
- الإنجازات: شروط التقدم والإنجاز والحالة المشتقة، دون تعديل القيم المشتقة يدويًا.
- الإعدادات: المنطقة الزمنية، بداية الأسبوع، التذكيرات التجريبية، التصدير، الخصوصية، وحالة تخزين النموذج الأولي.

## القرارات الموحّدة لقاعدة البيانات

### العلاقات الأساسية

- المستخدم 1:N مع عاداته وسجلاته اليومية وانتكاساته ويومياته وكتبه وجلسات قراءته ومراجعاته وإنجازاته وتذكيراته ووسومه.
- العادة 1:N مع السجلات اليومية، والانتكاسات، ونسخ الجدول/الهدف المؤرخة، وفترات الإيقاف، والتذكيرات.
- العادة M:N مع الكتب عبر `habit_books`، ومع اليوميات عبر `journal_habits`، ومع مراجعات الأسابيع عبر `weekly_focus_habits`.
- اليومية M:N مع الوسوم عبر `journal_entry_tags`؛ ويسمح بأكثر من تدوينة للمستخدم في اليوم نفسه.
- الكتاب 1:N مع جلسات القراءة `reading_sessions`؛ القراءة المسجلة بالجلسات هي المصدر الفعلي لحساب الصفحات، لا حقل `tracked_pages` غامض.
- العادات M:N مع عادات مرتبطة عبر `habit_relations` بعلاقة مسماة واتجاه/تماثل محدد، ومن دون تمثيل علاقة العادة-الكتاب أو العادة-اليومية داخل حقل منفرد.
- التركيز الأسبوعي 1:N مع عناصر الربط للعادات؛ قيد فريد لكل مستخدم وتاريخ بداية أسبوع.
- الإنجازات مرتبطة اختياريًا بعادة واحدة وبشرط محسوب؛ القيم الحالية ومؤشر الإنجاز بيانات مشتقة/مخزنة مؤقتًا لا يحررها المستخدم.

### الجداول التي سيغطيها المخطط

1. `users` و`user_preferences` (أو مرجع هوية المنصة إن فُعّل backend لاحقًا).
2. `habit_categories` و`habits`.
3. `habit_versions` لقواعد الجدولة والهدف والحد الأدنى والوحدة وتاريخ السريان، و`habit_pause_periods`.
4. `habit_daily_logs` بمفتاح موعد ثابت وحالة ولقطات goal/minimum/unit تاريخية.
5. `habit_relapses`.
6. `books` و`reading_sessions` و`habit_books`.
7. `journal_entries` و`journal_habits` و`journal_tags` و`journal_entry_tags`.
8. `weekly_focus` و`weekly_focus_habits`.
9. `achievements`.
10. `habit_relations` و`habit_reminders`.
11. `audit_events` أو آلية موحدة مكافئة للتغييرات الحساسة والحذف القابل للاستعادة.

### قواعد الجدولة والمقاييس

- تمثيل يومي، أيام أسبوع محددة، عدد مرات داخل أسبوع/شهر، كل N يوم/أسبوع/شهر، وموعد شهري محدد مع قاعدة صريحة لأيام الشهر غير الموجودة.
- `start_date` مطلوب و`end_date` اختياري؛ `NULL` يعني عادة مستمرة. تاريخ النهاية شامل، ولا توجد مواعيد بعده.
- المواعيد غير المجدولة محايدة. سلاسل الجدول المحدد تُحسب على المواعيد المجدولة، والهدف العددي الأسبوعي/الشهري يُحسب على الفترات المكتملة. لا يُحكم على الفترة الحالية قبل انتهائها.
- لا تُنشأ سجلات فائتة تلقائيًا لمجرد ملء التقويم؛ غياب سجل لموعد انتهى يُفسر كمفوّت في الحسابات فقط.
- تمييز `Done` و`Partial` و`Missed` و`Vacation/Excused` و`Skipped`، وفصل العادة المتوقفة مؤقتًا عن المؤرشفة.
- الكمية التي تبلغ الهدف = `Done`، وما يحقق الحد الأدنى دون الهدف = `Partial`، وما دون الحد الأدنى يفشل بعد إغلاق الموعد. `minimum` لا يتجاوز `goal`.
- تغييرات الجدول أو الهدف مؤرخة عبر `habit_versions`، فلا تعيد تفسير الماضي. تعديل/حذف السجلات القديمة أو الانتكاسات يعيد الحسابات المتأثرة ويحفظ أفضل نتيجة تاريخية.

### سلامة البيانات ودورة الحياة

- كل جدول مملوك للمستخدم يحمل `user_id` أو يضمن الملكية من خلال علاقة مركبة؛ وتوثق المفاتيح الأجنبية وسلوك `RESTRICT` و`SET NULL` و`CASCADE` لكل علاقة.
- المفاتيح المركبة/الفريدة تمنع تكرار سجل الموعد، تكرار علاقة الربط، أو تكرار مراجعة الأسبوع.
- أرشفة العادة هي الخيار الافتراضي وتحفظ التاريخ. الحذف القابل للاستعادة منفصل عن الحذف النهائي؛ حذف عادة ذات تاريخ يتطلب اختيارًا صريحًا لمصير السجلات التابعة.
- حذف كتاب لا يحذف سجلات القراءة/العادات، بل يفك الروابط المناسبة. حذف يومية لا يحذف سجل العادة.
- فهارس على `user_id` والتواريخ والمفاتيح الأجنبية وحقول البحث، وقيود تحقق للأهداف والتواريخ والحالات.

## خطة المواصفة والملفات

- `docs/HABIT_OS_UNIFIED_SPEC_AR.md`: وثيقة واحدة مدمجة، بالعربية، تشرح المنتج والافتراضات ومخطط العلاقات وكتالوج الجداول وحقولها وقواعد الملكية والمفاتيح والقيود والفهارس والسلوكيات وميزات كل شاشة وسياسات الحذف والخصوصية والتوسع.
- `database/schema.sql`: DDL علائقي متسق مع نموذج MySQL 8 الذي تدعمه بنية WebDev عند إضافة قاعدة فعلية، مع مفاتيح وفهارس وقيود وتعليقات واضحة. لا تُفعّل قاعدة مدارة أو تنفذ migrations في هذه المرحلة إلا إذا كان ذلك مطلوبًا لاحقًا.
- `README.md`: طريقة تشغيل النموذج الأولي، وطريقة إعادة ضبط بيانات العرض، والتنبيه إلى أن البيانات محلية في المتصفح وليست حسابًا أو قاعدة إنتاجية.

## خطة واجهة المستخدم

### البنية والمكوّنات

تنفيذ واجهة HTML/CSS/JavaScript مقسمة إلى ملفات واضحة، مع موجّه داخلي بسيط وقائمة جانبية عربية RTL. يستخدم النموذج الأولي `localStorage` للتفاعل وحفظ بيانات العرض داخل المتصفح فقط، مع طبقة تخزين قابلة للاستبدال بخدمات API لاحقًا. لا يوجد تسجيل دخول أو مزامنة أو backend ضمن هذا النطاق.

تتضمن مناطق الواجهة:

- شريط تنقل جانبي يميني للأقسام، ورأس صفحة يعرض التاريخ والبحث والإجراء الرئيسي.
- لوحة يومية فيها أزرار تسجيل سريع، وتقدم بصري لكل عادة، مع فصل العادات الجيدة عن بطاقة الأيام النظيفة للعادات السيئة.
- صفحات/عروض منفصلة للعادات، السجل اليومي، الانتكاسات، الجورنال، الكتب، التركيز الأسبوعي، الإنجازات، والإعدادات.
- نماذج إضافة وتعديل ملائمة لكل كيان؛ عرض صفحات القراءة من جلسات القراءة؛ ربط متعددة-إلى-متعددة في الواجهة بدل حقول FK مفردة متعارضة.
- بحث وتصفية وفرز، حالات تحميل/فراغ/خطأ، رسائل تأكيد للحذف، استعادة/عرض المؤرشف حيث ينطبق، ومفاتيح واضحة للأفعال الأساسية.
- واجهة متجاوبة لسطح المكتب والجوال، اتجاه RTL فعلي، حالات تركيز لوحة المفاتيح، تباين كافٍ، واحترام `prefers-reduced-motion`.

### التوجه البصري

- **الحركة التصميمية:** لوحة تحريرية هادئة للصحة والإنتاجية، تجمع وضوح الواجهة السويسرية مع دفء مفكرة شخصية.
- **المبادئ:** قراءة سهلة؛ التركيز على فعل اليوم لا كثرة المؤشرات؛ تاريخ مرئي بلا لوم؛ عناصر واجهة متسقة وقابلة للوصول.
- **الألوان:** خلفية عاجية دافئة لتخفيف قسوة اللوحات؛ أخضر عميق للإنجاز والثبات؛ أزرق مخضر مميز للهوية؛ مرجاني محدود للتنبيه لا للعقوبة؛ رمادي محايد للمعلومات الثانوية.
- **التركيب:** شريط جانبي يمين ثابت على الشاشات الواسعة، مساحة عمل واسعة بمحاذاة بداية الصفحة، وشريط ملخص أسبوعي/سياقي جانبي بدل شبكة مركزية مزدحمة. على الجوال تتحول الملاحة إلى قائمة قابلة للفتح.
- **عناصر التوقيع:** مسار بصري دائري صغير للتقدم، شريط أيام أسبوعي بعلامات بسيطة، شارات هادئة للأهداف/الاستثناءات.
- **التفاعل والحركة:** فعل تسجيل العادة بنقرة؛ نوافذ جانبية قصيرة للنماذج؛ انتقالات 150–220ms للظهور والتأكيد فقط؛ لا رسوم مستمرة؛ تقليل الحركة عند تفضيل النظام.
- **الخطوط:** `Tajawal` أو `Noto Sans Arabic` للواجهة العربية مع `system-ui` كبديل، و`Inter` أو `system-ui` للأرقام/المعرفات اللاتينية؛ لا يتوقف العرض على تحميل خط خارجي.
- **جوهر العلامة:** مساحة هادئة لإدارة العادات والتأمل والقراءة، شخصية واضحة ومنظمة ومشجعة.
- **صوت العلامة:** مباشر وداعم بلا لوم؛ أمثلة: «خطوة صغيرة محسوبة.» و«اليوم غير المجدول لا يقطع تقدمك.»
- **الشعار:** كلمة «عادة» بعلامة مسار دائري مفتوح يرمز إلى الاستمرارية المرنة لا إلى سلسلة مثالية.
- **لون العلامة:** أخضر مزرق عميق مميز، يستخدم للعناصر الرئيسية وعلامة Habit OS.

### الاستثناءات والنطاق غير المشمول

- لن تُنشأ كيانات مكررة للمشاريع أو التعلم أو المال أو المنزل أو المحتوى؛ تُعرض كتصنيفات/سياقات وروابط خارج نطاق ملكية Habit OS.
- التذكيرات في النموذج الأولي إعدادات وتجربة واجهة فقط، وليست إشعارات نظام فعلية.
- لا تكامل صحة، ولا حسابات مستخدمين، ولا تخزين سحابي أو نشر عام أو إرسال بيانات خارجية في هذه المرحلة.

## خطة التنفيذ

1. إعادة التحقق من الملفين المصدرين وقراراتهما، وإعداد مصفوفة توحيد العلاقات والقرارات التي تحسم التعارضات.
2. إتمام تصميم الكيانات والحقول والمفاتيح والقيود وسياسات الحذف، ثم كتابة المواصفة العربية وملف SQL.
3. بناء نظام التنقل العربي RTL ونظام التصميم والمكوّنات الأساسية وحالات الاستجابة للجوال.
4. تنفيذ أقسام Habit OS من اليوم والتركيز والعادات إلى السجل اليومي والانتكاسات واليوميات والكتب/جلسات القراءة والتركيز الأسبوعي والإنجازات والإعدادات.
5. تنفيذ سلوك النموذج الأولي مع بيانات محلية: إضافة/تعديل/أرشفة/حذف أو استعادة حيث ينطبق، تسجيل سريع، ربط الجداول، والاحتفاظ بالبيانات بعد إعادة تحميل الصفحة على المتصفح نفسه.
6. مطابقة الواجهة والبيانات مع المواصفة الموحدة وإصلاح أي اختلاف قبل التسليم.

## التحقق ومعايير الاكتمال

- التحقق من أن كل علاقة مذكورة في ERD تقابل مفاتيح أجنبية/جداول ربط محددة في المخطط، وألا تبقى روابط `habit_id` مفردة حيث يلزم M:N.
- التحقق من قيود ملكية المستخدم والفهارس والقيود الفريدة والقيم المشتقة وسياسات الحذف؛ والتأكد من أن جلسات القراءة هي مصدر تقدم الكتب.
- تشغيل واجهة المعاينة والتحقق من أن `/manus-routes.json` يعيد JSON مطابقًا لمسارات الواجهة.
- التحقق بصريًا من شاشة لوحة اليوم وقسمين أو أكثر على سطح المكتب والجوال، مع كون اتجاه RTL سليمًا وعدم وجود قص أو تمرير أفقي غير مقصود.
- تجربة تفاعلات أساسية من الواجهة: إضافة وتعديل وأرشفة/حذف عنصر واستعادة ما يدعمه النموذج، تسجيل عادة، إضافة جلسة قراءة، إنشاء تدوينة ثانية في اليوم، وإنشاء تركيز أسبوعي مع روابط صحيحة.
- إعادة تحميل الواجهة والتأكد من استمرارية بيانات النموذج المحلي، وإظهار تنبيه واضح أن هذه بيانات على هذا المتصفح وليست مزامنة/قاعدة إنتاجية.
- لا يتم النشر العام؛ التسليم يكون بمواصفة قابلة للتنزيل ورابط معاينة المشروع فقط، ما لم يطلب المستخدم النشر لاحقًا.

## الافتراضات والمخاطر المفتوحة

1. **افتراض التنفيذ:** المقصود تصميم قاعدة البيانات وتوثيق DDL، مع واجهة نموذج أولي تفاعلية؛ لا تشغيل backend أو قاعدة بيانات إنتاجية أو تسجيل دخول الآن. بيانات النموذج في localStorage فقط. إذا كان المقصود تطبيقًا متعدد المستخدمين محفوظًا على السحابة، فهذا يضيف إعداد backend/قاعدة وهو قرار نطاق منفصل.
2. يستهدف ملف SQL MySQL 8 لتوافقه مع بنية WebDev المُدارة عند توصيل backend لاحقًا؛ يجب إبقاء قواعد المجال مستقلة عن SQL قدر الإمكان.
3. يسجل النظام اليوميات على مستوى إدخال مرن يسمح بأكثر من تدوينة في اليوم؛ وروابط اليومية بالعادات متعددة.
4. جلسات القراءة هي المصدر الوحيد المعياري لتقدم الصفحات، مع دعم استيراد صفحات قبل بداية التتبع.
